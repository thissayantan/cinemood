# Phase 5 — Settings page

Per-user LLM provider config now lives at KV `user:{id}:llm_config` as an AES-GCM ciphertext (`apps/api/src/lib/crypto.ts`, IV prepended, base64 envelope, key from `env.LLM_CONFIG_KEY`). `apps/api/src/lib/user-llm.ts` handles `read/write/delete` and the previously-stub `resolveLlmConfig` now consults the user override before falling back to the global `app_settings` row. Routes: `GET /api/settings/llm` returns `{effective, isUserOverride, catalog}` (the API key never leaves the Worker — only `hasKey: boolean`); `PUT` validates with a discriminated zod union plus a refine that calls `isValidModel(provider, model)` against the catalog and lets the client omit `apiKey` to keep the existing one; `DELETE` clears the override; `POST /api/settings/llm/test` runs the parser against a fixed query through `runTestConnection` and surfaces either `sampleOutput` or a structured error. Frontend route `/settings/search` (linked from the avatar menu) renders provider tiles, a model select that filters from the live catalog, an API-key input with a "Saved" badge when the server reports `hasKey`, and Test/Save/Reset buttons that pretty-print the parser sample on success. Smoke test (against `wrangler dev --remote`): default GET shows Cloudflare/gpt-oss-20b with `isUserOverride=false`; PUT to gpt-oss-120b succeeds and flips the override flag; `POST .../test` round-trips through Workers AI and returns a valid `ParsedQuery` (`{type:["series"], genres:["Science Fiction"], min_rating:8, release_after:"2024"}` for the locked test query); a bogus model and an Anthropic config without an API key are both rejected with `VALIDATION`; DELETE resets cleanly back to the global default.
