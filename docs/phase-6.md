# Phase 6 — Bulk import

Built the import wizard end-to-end. Frontend `/import` page (linked from the avatar menu) has a three-tab input — paste-list, CSV upload, Google Takeout JSON upload. Client-side parsers in `apps/web/src/lib/import-parsers.ts` handle the textarea (one title per line, with `(YYYY)` suffix), CSV with column auto-detection (recognises Letterboxd `Letterboxd URI`, IMDb `Title Type`+`IMDb Rating`, Trakt `rank`+`title`, and a generic single-column fallback), and a recursive Takeout JSON walker that dedupes on title and pulls year/type hints when present. Each candidate gets `{raw, title, year?, type?}` and is sent to `POST /api/import/resolve`, which scores TMDB matches via `apps/api/src/lib/import-resolve.ts` (normalized-title equality, year proximity, type-hint match, position bonus, capped at 1.0) and returns one of `matched | ambiguous | unmatched` with up to four alternatives. The review UI shows a checkbox row per item with a poster preview, status pill (`matched / ambiguous / no match`), and a per-row alternative dropdown — selecting a row wires it into a final `{tmdb_id, type}[]`. `POST /api/import/commit` runs the full TMDB-detail + OMDB rating + `upsertTitle` + `addToWatchlist` pipeline and schedules an `addTitleToIndex` via `executionCtx.waitUntil` for each item, so imports re-embed exactly like single adds. Smoke test (`wrangler dev --remote`): four-line resolve returned `Past Lives (2023)→matched 1.00`, `The Bear→matched 0.85 (series 2022)`, `definitely-not-a-real-movie-xyzzy→unmatched 0.00`, `Mad Men→matched 0.85 (series 2007)`; the commit endpoint added `Past Lives (666277)` and `The Bear (136315)` and the watchlist now lists them alongside the existing entries.
